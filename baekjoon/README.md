# 백준 풀이 알고리즘 정리

백준에서 푼 문제의 핵심 알고리즘과 풀이 흐름을 정리합니다. 새 문제를 풀 때마다 아래에 추가합니다.

## 문제 보고 알고리즘 떠올리기

| 신호 | 떠올릴 것 | 예시 |
|---|---|---|
| 격자/지도, "최단 거리", "최소 칸 수" | BFS | 미로 탈출 |
| 가장 작은/큰 것을 계속 꺼낸다, 작업 순서 | 힙 (우선순위 큐) | 디스크 컨트롤러 |
| 모든 섬/도시를 최소 비용으로 연결 | MST (크루스칼 + 유니온파인드) | 섬 연결하기 |
| "최소 K", K 범위가 매우 큼, "K면 되나?" 확인은 쉬움 | 이분탐색 (매개변수 탐색) | 6236, 입국심사 |
| 두 수의 합/차, 정렬해도 됨 | 정렬 + 투 포인터 | 1253 |
| 넣거나 안 넣거나, 최대 가치 | DP (배낭) | 12865 |
| N이 10~15 이하로 작음 | 완전탐색 / 백트래킹 | 피로도 |

**제한으로 거르기** (1초 ≈ 1억 번): N ≤ 10 → 전부 해보기 / N ≤ 2,000 → O(N²) / N ≥ 100,000 → O(N log N) 이하

**시험장 전략**: 떠오르지 않으면 무식한 방법이라도 먼저 제출해서 부분 점수를 챙기고, 그다음 위 표를 보며 개선한다.

## 1253 좋다

**문제 요약**
N개의 수 중에서, **다른 두 수의 합**으로 나타낼 수 있는 수(좋은 수)의 개수를 구한다.
N ≤ 2,000, |값| ≤ 1,000,000,000. 같은 값이 여러 번 나올 수 있고, 위치가 다르면 다른 수로 본다.

**왜 3중 for문은 안 되나**
- i, j, k를 전부 도는 방법은 2000³ = 80억 번 → 시간 초과.
- 같은 k를 여러 쌍(1+3, 3+1 …)으로 중복해서 세서 답도 커진다. "좋은 수의 **개수**"라서 k 하나당 최대 1번만 센다.

**알고리즘: 정렬 + 투 포인터**
1. 배열을 오름차순 정렬한다.
2. 검사할 수 `num[k]`마다 `i = 0`(제일 작은 쪽), `j = N-1`(제일 큰 쪽)에서 시작한다.
3. `i == k`나 `j == k`이면 자기 자신은 못 쓰니 건너뛴다.
4. `s = num[i] + num[j]`
   - `s == num[k]` → 좋은 수! 세고 바로 다음 k로 (`break`)
   - `s < num[k]` → 합을 키워야 하니 `i++`
   - `s > num[k]` → 합을 줄여야 하니 `j--`
5. 정렬돼 있어서 포인터를 한 방향으로만 움직여도 모든 후보를 놓치지 않는다.

**복잡도**: k마다 while이 최대 N번 → O(N²) = 400만 번.

```cpp
sort(num, num + N);
for (int k = 0; k < N; k++) {
    int i = 0, j = N - 1;
    while (i < j) {
        if (i == k) { i++; continue; }
        if (j == k) { j--; continue; }
        long long s = num[i] + num[j];
        if (s == num[k]) { cnt++; break; }
        else if (s < num[k]) i++;
        else j--;
    }
}
```

**헷갈렸던 점**
- 값이 최대 10억이라 두 수를 더하면 int 범위(약 21억)를 넘을 수 있다 → `long long`, 입력은 `%lld`.
- `scanf_s`는 Visual Studio 전용 → 시험장에서는 `scanf`. (VS에서는 맨 위에 `#define _CRT_SECURE_NO_WARNINGS`)
- C++ `sort`는 `using namespace std;`가 있어야 한다. C는 `qsort` + cmp 함수(`(p > q) - (p < q)`).
- 음수, 0이 섞여 있어도 정렬 + 투 포인터로 그대로 된다 (예: 0 0 0 → 3개 모두 좋은 수).

## 6236 용돈 관리

**문제 요약**
N일 동안 매일 쓸 돈이 정해져 있다. 은행에서 한 번에 **K원씩만** 인출할 수 있고, 지갑 돈이 오늘 쓸 돈보다 모자라면 남은 돈을 넣고 다시 K원을 인출한다. 인출을 **M번 이하**로 하게 만드는 **최소 K**를 구한다.
N, M ≤ 100,000, 하루 금액 ≤ 10,000.

**아이디어: "K를 정해놓고 되는지 확인" + 업다운 게임**
- K를 하나 정하면 인출 횟수는 하루씩 따라가며 O(N)에 셀 수 있다 → `count(K)`
- K가 클수록 인출 횟수는 줄어든다. 그래서 "되는 K"와 "안 되는 K"가 경계 하나로 나뉜다 → 이분탐색으로 경계를 찾는다.
- 이렇게 "답을 직접 구하기 어려울 때, 답을 하나 찍고 되는지 확인하는 문제로 바꾸는 것"을 **매개변수 탐색(파라메트릭 서치)** 이라고 한다. (프로그래머스 입국심사, 징검다리도 같은 유형)

**탐색 범위**
- `lo` = 하루 금액 중 최댓값: 이보다 작으면 그날 쓸 돈을 한 번에 못 뽑아서 불가능
- `hi` = 전체 합: 처음 1번 뽑은 돈으로 N일을 다 쓸 수 있어서 무조건 성공
- 답은 항상 `lo ≤ K ≤ hi` 안에 있다.

**예제 따라가기** (`100 400 300 100 500 101 400`, M=5, lo=500, hi=1901)
| lo | hi | mid | 인출 횟수 | M 이하? |
|---|---|---|---|---|
| 500 | 1901 | 1200 | 2 | 된다 → hi=1199 |
| 500 | 1199 | 849 | 3 | 된다 → hi=848 |
| … | | | | |
| 500 | 500 | 500 | 5 | 된다 → hi=499, 끝 |

답 500. 1401개를 다 해보지 않고 10번 만에 찾는다.

```cpp
int count(int k) {
    int now_money = k;
    int cnt = 1;                         // 처음에 1번 뽑고 시작
    for (int i = 0; i < N; i++) {
        if (money[i] <= now_money) now_money -= money[i];   // 지갑 돈으로 충분
        else { cnt++; now_money = k - money[i]; }           // 모자라면 새로 뽑기
    }
    return cnt;
}

int ans = hi;
while (lo <= hi) {
    int mid = (lo + hi) / 2;
    if (count(mid) <= M) { ans = mid; hi = mid - 1; }   // 된다 → 더 작은 K 시도
    else lo = mid + 1;                                  // 안 된다 → K 키우기
}
```

**복잡도**: count가 O(N), 이분탐색이 log(합) ≈ 30번 → O(N log(합)).

**헷갈렸던 점**
- count에서 비교 대상은 K가 아니라 **지금 지갑에 남은 돈**(`now_money`).
- 처음 인출도 1번이다 → `cnt = 1`로 시작.
- 모자랄 때 지갑은 `+= k`가 아니라 `= k` (남은 돈은 통장에 넣으니까).
- 이분탐색에서 `mid++`/`mid--`가 아니라 **`lo`, `hi`를 움직인다**. mid는 매번 새로 계산된다.
- **된다 → `hi = mid - 1`, 안 된다 → `lo = mid + 1`**. `lo = mid - 1`로 쓰면 무한루프. 반복 조건은 `lo <= hi`.
