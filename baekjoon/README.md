## 1253 좋다

**문제 요약**
N개의 수 중에서, **다른 두 수의 합**으로 나타낼 수 있는 수(좋은 수)의 개수를 구한다.
N ≤ 2,000, |값| ≤ 1,000,000,000. 같은 값이 여러 번 나올 수 있고, 위치가 다르면 다른 수로 본다.

**왜 3중 for문은 안 되나**
- i, j, k를 전부 도는 방법은 2000³ = 80억 번 → 시간 초과.
- 같은 k를 여러 쌍(1+3, 3+1 …)으로 중복해서 세서 답도 커진다. "좋은 수의 **개수**"라서 k 하나당 최대 1번만 센다.

**알고리즘: 정렬 + 투 포인터**
1. 배열을 오름차순 정렬한다.
2. 검사할 수 `num[k]`마다 `i = 0`(제일 작은 쪽), `j = N-1`(제일 큰 쪽)에서 시작한다.
3. `i == k`나 `j == k`이면 자기 자신은 못 쓰니 건너뛴다.
4. `s = num[i] + num[j]`
   - `s == num[k]` → 좋은 수! 세고 바로 다음 k로 (`break`)
   - `s < num[k]` → 합을 키워야 하니 `i++`
   - `s > num[k]` → 합을 줄여야 하니 `j--`
5. 정렬돼 있어서 포인터를 한 방향으로만 움직여도 모든 후보를 놓치지 않는다.

**복잡도**: k마다 while이 최대 N번 → O(N²) = 400만 번.

```cpp
sort(num, num + N);
for (int k = 0; k < N; k++) {
    int i = 0, j = N - 1;
    while (i < j) {
        if (i == k) { i++; continue; }
        if (j == k) { j--; continue; }
        long long s = num[i] + num[j];
        if (s == num[k]) { cnt++; break; }
        else if (s < num[k]) i++;
        else j--;
    }
}
```

**헷갈렸던 점**
- 값이 최대 10억이라 두 수를 더하면 int 범위(약 21억)를 넘을 수 있다 → `long long`, 입력은 `%lld`.
- `scanf_s`는 Visual Studio 전용 → 시험장에서는 `scanf`. (VS에서는 맨 위에 `#define _CRT_SECURE_NO_WARNINGS`)
- C++ `sort`는 `using namespace std;`가 있어야 한다. C는 `qsort` + cmp 함수(`(p > q) - (p < q)`).
- 음수, 0이 섞여 있어도 정렬 + 투 포인터로 그대로 된다 (예: 0 0 0 → 3개 모두 좋은 수).
