# [Lv.3] 디스크 컨트롤러

- 링크: https://school.programmers.co.kr/learn/courses/30/lessons/42627
- 사이트 / 난이도: 프로그래머스 / Lv.3
- 유형: 힙, 시뮬레이션 (현대오토에버 기출 1번 유형과 비슷)
- 푼 날짜: 2026-10-23

## 풀이 아이디어 (solution.cpp, 내 풀이)
1ms씩 시간을 흘리며 시뮬레이션한다.
- 그 시각에 요청된 작업을 대기 큐(배열 3개)에 넣는다.
- 디스크가 비어 있으면(`now_num == -1`) 대기 큐를 훑어서 우선순위 1등을 고른다.
  소요시간 → 요청 시각 → 번호 순으로, 앞 기준이 같을 때만 다음 기준을 본다.
- 고른 작업은 맨 끝 작업으로 덮어써서 큐에서 지운다. 덮어쓰기 전에 요청 시각을 `now_start`에 저장한다.
- 남은 시간이 0이 되면 끝난 시각 `time + 1`로 반환 시간을 더한다.

## 더 쉬운 풀이 (solution_easy.cpp)
대기 큐를 따로 만들지 않는다. 디스크가 빌 때마다 `jobs` 전체에서 "도착했고 아직 안 한 작업" 중 1등을 고르고,
고르자마자 `time += 소요시간`으로 끝까지 실행한다. `used[]` 표시 하나로 큐 삭제와 현재 작업 상태 관리를 없앴다.

## 시간 / 공간 복잡도
- 내 풀이: O(전체 시간 × n), 전체 시간 ≤ 약 50만, n ≤ 500
- 쉬운 풀이: O(n²) + 쉬는 구간의 1ms씩
- 시간이 10억까지 가거나 n이 20만이면 둘 다 느리다 → 다음 작업 시각으로 점프 + 힙

## 헷갈렸던 점, 배운 점
- 여러 기준 비교 중간에 `best = i`를 먼저 넣으면 자기 자신과 비교하게 된다. 비교가 끝난 뒤 한 번만 바꾸기.
- `time += 소요시간`으로 점프하고 `time == 요청시각`으로 넣으면, 건너뛴 구간의 작업을 놓쳐서 무한 루프.
- if 안에서 `int now_num = 0;`처럼 `int`를 다시 붙이면 바깥 변수가 아닌 새 변수가 생긴다.
- `now_num`(작업 번호)으로 `q_start`(큐 칸 번호 배열)를 읽으면 예제만 맞고 채점에서 틀린다.
- 1ms씩 흘리는 방식에서는 끝나는 시각이 `time + 1`.
- 소요시간 순으로 미리 정렬하면 우선순위 비교 자체를 없앨 수 있다 (같은 소요시간끼리는 순서를 바꿔도 반환 시간 합이 같다).
