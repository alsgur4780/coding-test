# [Lv.2] 피로도

- 링크: https://school.programmers.co.kr/learn/courses/30/lessons/87946
- 사이트 / 난이도: 프로그래머스 / Lv.2
- 유형: 완전탐색, 백트래킹(DFS)
- 푼 날짜: 2026-10-24

## 풀이 아이디어 (solution.c)
던전이 최대 8개라 들어가는 **모든 순서**를 다 해봐도 8! = 40,320가지라 충분하다.
모든 순서를 도는 방법이 DFS 백트래킹이다.
1. 지금까지 간 개수로 최댓값 갱신
2. 아직 안 간 던전 중 최소 필요 피로도를 만족하는 것을 하나 골라
3. 방문 표시 → 피로도 깎고 재귀 → **방문 표시 되돌리기** (그래야 다른 순서에서 다시 고를 수 있다)

예) k=80, A[80,20] B[50,40] C[30,10]
```
dfs(80, 0개)
├─ A 들어감 → dfs(60, 1개)
│   ├─ B → dfs(20, 2개) → C 못 감(30 필요)... 끝
│   └─ C → dfs(50, 2개) → B → dfs(10, 3개) ★ 최대 3
├─ B 들어감 → dfs(40, 1개) → A 못 감, C → dfs(30, 2개) ...
└─ C 들어감 → dfs(70, 1개) → A 못 감, B → dfs(30, 2개) ...
```

## 시간 / 공간 복잡도
- O(N!) (N ≤ 8 → 최대 40,320가지), 공간 O(N)

## 헷갈렸던 점, 배운 점
- 제한이 작으면(N ≤ 10) 전부 해보기를 먼저 떠올린다.
- 재귀에서 돌아온 뒤 `chk[i] = 0`으로 되돌리는 게 백트래킹의 핵심.
- 프로그래머스 C에서는 2차원 배열이 `int** dungeons` + 행 길이 `dungeons_rows`로 들어온다.
- 반환값이 없는 함수는 `void dfs(...)`로 쓰는 게 깔끔하다.
